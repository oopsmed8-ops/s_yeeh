# Sidahmed-auto — ملاحظات مراجعة وتطوير لوحة الإدارة

## ما تم إصلاحه في هذه النسخة

1. **Panoramica:** كان `showSkeletons()` يستبدل شبكة الإحصائيات بعناصر لا تحمل معرّفات `statPublished` و`statDrafts` و`statLeads` و`statReviews`. لذلك يفشل `loadOverview()` عند محاولة تحديث عنصر غير موجود وتبقى الواجهة في حالة تحميل. تم الإبقاء على العناصر الأصلية وتغيير قيمها فقط، مع معالجة مستقلة لأخطاء الاستعلامات.
2. **الشعار:** أزيلت فلاتر `brightness(0.15)` التي كانت تغيّر ألوان الشعار في الوضع الفاتح. الشعار الحالي نصه أبيض وحرف G وعناصره حمراء على خلفية شفافة؛ لذلك وضعت له سطحاً أسود صغيراً حتى يظل مقروءاً في الوضعين دون تغيير ألوانه.
3. **القائمة الجانبية:** زر إغلاق واضح، إغلاق بالنقر على الخلفية، دعم Escape، وإعلان حالة `aria-expanded`.
4. **تفاصيل السيارات:** الضغط على صف السيارة يفتح نافذة تفاصيل تعرض الحقول المتوفرة والصور، مع زر انتقال إلى نموذج التعديل. النافذة متوافقة مع اللغات الثلاث.
5. **الفلاتر:** الحالة والفئة تعملان عبر كل صفحات DataTables.
6. **تسجيل الدخول:** لا يسمح بالدخول إذا فشل استعلام الملف الشخصي أو لم يوجد سجل أو لم يكن الدور `admin`.
7. **الصور:** تنظيف ملفات R2 عند حذف السيارة، ومحاولة تنظيف الملف إذا فشل حفظ سجل الصورة في قاعدة البيانات. أضيف فحص توقيع الملف على Worker حتى لا يكفي تزوير Content-Type.
8. **Worker health:** يعرض فحص الصحة حالة وجود R2 وإعداد Supabase دون كشف أي مفاتيح.

## ما لم يتم اعتماده بعد — يحتاج قراراً/تنفيذاً لاحقاً

- تبويبا **Richieste** و**Recensioni** ما زالا واجهتين تمهيديتين (`comingSoon`) وليسا نظامي إدارة مكتملين.
- لا توجد إدارة صور كاملة داخل محرر السيارة: حذف صورة منفردة، تغيير الصورة الرئيسية، السحب لإعادة الترتيب، ومعاينة الصور قبل الحفظ.
- لا توجد سجلات تدقيق توضح من عدّل سيارة أو حذفها ومتى.
- لا توجد صفحة إعدادات للملف الإداري أو تغيير كلمة المرور أو تفعيل MFA.
- لا توجد أدوات نسخ احتياطي/استعادة أو تصدير CSV للسيارات والطلبات.

## خارطة الطريق المقترحة

### المرحلة A — إكمال الإدارة اليومية
- إدارة الطلبات: تفاصيل العميل، السيارة المطلوبة، تاريخ الطلب، الحالة (جديد/قيد المتابعة/مغلق)، ملاحظات داخلية، وروابط اتصال مباشرة.
- إدارة التقييمات: عرض المراجعة، اعتماد/رفض، إخفاء، وإظهار التقييمات المعتمدة فقط على الموقع العام.
- مدير صور السيارة: صورة رئيسية، ترتيب بالسحب، حذف منفرد مع تنظيف R2، ورفع متعدد مع تقدم واضح.

### المرحلة B — الاعتمادية والأمان
- تفعيل MFA لحسابات الإدارة، وانتهاء جلسة واضح، ورسالة عند انقطاع الاتصال.
- مراجعة سياسات RLS لكل جدول، خاصة `profiles`, `cars`, `car_images`, `inquiries`, `reviews`، واختبار مستخدم غير إداري.
- تسجيل عمليات الإدارة (audit log) وعدم السماح بالحذف النهائي دون تأكيد ثانٍ أو إمكانية أرشفة.
- تنظيف دوري لملفات R2 اليتيمة ومقارنة مفاتيح التخزين مع سجلات `car_images`.
- إضافة حد أقصى لعدد الصور لكل سيارة والتحقق من أبعاد الصور وضغطها قبل الرفع.

### المرحلة C — التحليلات وتجربة الاستخدام
- إحصائيات حسب الفترة الزمنية، أكثر السيارات مشاهدة، الطلبات حسب الحالة، ومعدل التحويل.
- بحث متقدم بالميزانية والسنة والماركة والموديل، مع حفظ الفلاتر.
- إشعارات داخل لوحة الإدارة للطلبات الجديدة والتقييمات المعلقة.
- تصدير CSV/PDF، وسجل نشاط، وواجهة إعدادات عامة.

## تعليمات نشر النسخة

1. احتفظ بنسخة محلية من `.env` ولا تستبدلها بملف فارغ. لم يُضمّن `.env` في حزمة المراجعة لحماية أسرارك.
2. شغّل `py build-config.py` بعد التأكد من وجود القيم المحلية الصحيحة. لا ترسل `SUPABASE_SECRET_KEY` إلى المتصفح.
3. انشر ملفات الموقع مع `config.js` العام، وانشر `worker.js` في Cloudflare مع ربط R2 باسم `BUCKET` وضبط أسرار Supabase و`ALLOWED_ORIGIN`.
4. في الاختبار المحلي عبر `python -m http.server 8088` استخدم عنواناً واحداً ثابتاً، وأضف أصله إلى `ALLOWED_ORIGIN` مثل `http://localhost:8088` أو `http://127.0.0.1:8088`.
5. افتح `https://عنوان-worker/api/health` وتأكد أن `ok` و`bucket` و`supabaseConfigured` صحيحة.
6. اختبر مسؤولاً صحيحاً، ومستخدماً عادياً، ورفع صورة صحيحة، وملفاً أكبر من 10MB، ونوعاً مزيفاً، وحذف سيارة لها صور.

## حدود الفحص الحالي

تم فحص ملفات HTML/JS/CSS وWorker محلياً وإجراء فحص صياغة JavaScript. لم يتم إجراء تسجيل دخول حقيقي إلى Supabase أو اختبار R2 حي لأن ذلك يتطلب الوصول إلى إعدادات حسابك. كما تعذر تشغيل Vite build من مجلد `node_modules` المرفق لأن الحزمة تحتوي على Rolldown native binding غير متوافق مع بيئة الفحص؛ أعد تثبيت الحزم محلياً على Windows باستخدام `npm install` قبل `npm run build` إذا كنت تستخدم Vite.
